# Деплой Telegram бота на Render

## ⚠️ Главная проблема

Ваш бот не запускается, потому что **переменная окружения `BOT_TOKEN` не установлена на Render**.

Из логов: `[dotenv@17.2.3] injecting env (0) from .env` - это значит, что dotenv загрузил 0 переменных, потому что файл `.env` не попадает в репозиторий (он в `.gitignore`).

## ✅ Решение

### Шаг 1: Установите переменную окружения на Render

1. Откройте ваш сервис на Render: https://dashboard.render.com/web/srv-d3uv3of5r7bs73fr0it0
2. Перейдите в **Environment** (левое меню)
3. Нажмите **Add Environment Variable**
4. Добавьте:
   - **Key**: `BOT_TOKEN`
   - **Value**: ваш токен от BotFather (например: `1234567890:ABCdefGHIjklMNOpqrsTUVwxyz`)
5. Нажмите **Save Changes**

### Шаг 2: Задеплойте обновленный код

```bash
git add .
git commit -m "Add HTTP server for Render and BOT_TOKEN validation"
git push origin main
```

Render автоматически задеплоит новую версию.

## 📝 Что было исправлено в коде

1. **Добавлена проверка `BOT_TOKEN`** - бот не запустится без токена и покажет понятное сообщение
2. **Добавлен HTTP сервер** - Render Web Service требует открытый порт для health checks
3. **Улучшено логирование** - теперь видно, когда бот успешно запустился

## 🔄 Альтернативный вариант (Background Worker)

Если не хотите использовать Web Service, можете создать **Background Worker**:

1. Удалите текущий Web Service
2. Создайте новый сервис типа **Background Worker**
3. Установите переменную `BOT_TOKEN`
4. Команда запуска: `node bot.js`
5. В этом случае можно убрать HTTP сервер из кода

**Преимущество Background Worker**: не требует открытого порта, меньше ресурсов.

## 🐛 Проверка после деплоя

После успешного деплоя в логах должно появиться:
```
✅ Бот запущен успешно!
🌐 HTTP сервер запущен на порту 10000
```

Если видите ошибку `BOT_TOKEN не установлен` - вернитесь к Шагу 1.

## 📱 Тестирование бота

1. Откройте Telegram
2. Найдите вашего бота
3. Отправьте команду `/start`
4. Бот должен ответить и показать клавиатуру с темами
